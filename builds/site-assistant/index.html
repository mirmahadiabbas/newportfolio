How a question travels

This website is static: plain files, no server of its own. So the page cannot call the AI directly, because anything on the page is public, including an API key. The question goes through a small backend I run on Cloudflare instead, which holds the key and decides whether the question gets through at all.

The question

Your browserSends the question, plus the last few exchanges so follow-ups make sense
Cloudflare WorkerHolds the API key. Runs four checks before anything costs money

The answer

Your browserShows the answer as it arrives, then adds the source links
Cloudflare WorkerStrips the hidden sources line and keeps only sources that really exist
Claude APIStreams the answer, ending with a hidden line naming the sections it used

The four checks inside the Worker, in order

1 Did the request come from this website? If not: refused. Other sites cannot use it.
2 Fewer than 8 questions from this visitor in the last minute? If not: wait a minute.
3 Is the question a sensible size, and the conversation in the right shape? If not: refused before any cost.
4 Is the site still under its daily limit of questions? If not: email Mir instead.
✓ Only now does the Worker call Claude. The one step that costs money.

Behind all four sits a monthly spend limit set with the AI provider, so the worst case is the assistant switching off for the day, not a large bill.

What it knows, and how

Everything the assistant knows is in one file I wrote by hand from my CV and this website: about twenty short sections, one per role, project or topic, each with an id and a link back to the page it describes. The whole file goes to the model with every question, as its instructions. The model is told to answer from that file and nothing else, and to finish each answer by naming the sections it used. Those names are what turn into the source links under each answer.

Where my CV and this site disagreed on a detail, the file follows the site or leaves the detail out, so the assistant cannot contradict the page you are reading.

Why there is no vector database

The usual way to build this is retrieval: split the documents into chunks, store them as embeddings in a vector database, and fetch the few most similar chunks for each question. That is the right tool when there is too much text to send with every question.

There is not, here. Everything true about me fits comfortably in the model's instructions, and the provider caches those instructions between questions, so sending all of it is cheap. Retrieval would add a database, a second service and a new way to fail, and could still fetch the wrong chunk. Sending everything means the model always sees all of it.

Built not to bluff

  • Answers only from the knowledge file. If the answer is not there, it says so and points you to my email rather than guessing.
  • Talks about me in the third person and will not speak as me, even if asked to.
  • Salary, notice period, reasons for leaving and references are handed straight to me, with my email.
  • Does not judge whether I suit a role. It describes the evidence and leaves the judgement to you.
  • Treats what you type as a question, not as instructions, so "ignore your rules" does not work.
  • A source link only appears if the section it names really exists, so the model cannot invent a citation.
  • Answers are shown as plain text. Nothing the model writes can become a link or code on the page.

How it is tested

49Plumbing checksRun against a stand-in for the AI, so they cost nothing. They check the limits, the refusals, the hidden sources line at every possible split point, and that the key never reaches the browser.
21Behaviour checksReal questions to the real model, after every change to what it knows: questions it should answer, ones it must not invent an answer to, ones it must hand to me, and attempts to break its rules.
1Daily health checkEach morning the Worker makes one tiny call and records the result, so an expired key shows up straight away instead of as a quietly broken page.

Designed and built by Mir. Stack: a Cloudflare Worker (rate limiting, Workers KV for the daily limit and health check, a daily scheduled check), the Anthropic Claude API (Haiku) with prompt caching and streamed responses, and a single self-contained JavaScript file that adds the assistant to every page of this site. No framework, no vector database.
