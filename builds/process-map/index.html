Design decisions

  • The diagram is not an image. The model writes Mermaid code under locked-down syntax rules: capped nodes, restricted characters, labelled branches, so diagrams render reliably. Your browser draws it.
  • Analysis is labelled as candidates, not findings. The tool only knows what the description says, and it says so on the page.
  • Anything unclear is not guessed. It becomes a question for the process owner, which is how a business analyst would actually handle it.
  • Graceful failure: non-process input gets an explanation and a minimal diagram, never an invented analysis.

Honest limits

Single process per run Prose input only, English output Flowchart notation in v1, no swimlanes or BPMN yet Complex processes are summarised to a capped number of nodes

Your description is processed via the Anthropic Claude API to generate the analysis (API data is not used to train AI models) and is not saved to any database or document. Results exist only on your screen.

The interesting problem was reliability: LLMs write broken diagram syntax roughly one time in five if left free, so the model is constrained to a locked subset of Mermaid that renders consistently, and anything the description does not say becomes a question rather than a guess. Stack: Make.com (synchronous webhook), Anthropic Claude API (Sonnet), Mermaid.js, and vanilla HTML and JavaScript on this page.
